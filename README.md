# ✦ OVENQUILL ENVELOPES

Плагин подарочных конвертов для Minecraft Java Edition 26.2 на серверах Paper и Purpur.

OVENQUILL ENVELOPES создаёт уникальные подписанные конверты с реальными Minecraft-предметами внутри. Игрок открывает конверт правой кнопкой мыши, видит короткую анимацию и получает награды. Если инвентарь заполнен, предметы сохраняются в базе и не выбрасываются в мир.

> Версия: **1.0.0** · Minecraft: **26.2** · Java: **25+** · API: **Paper 26.2**

## Возможности

### Уникальные конверты

- Каждый экземпляр получает отдельный UUID.
- Служебные данные хранятся в `PersistentDataContainer`.
- HMAC-SHA256 защищает тип, версию и UUID от ручной подделки.
- Переименованный лист бумаги не распознаётся как конверт.
- Уже открытый или зарезервированный конверт нельзя использовать повторно.
- Изменение шаблона создаёт новую версию и не меняет уже выданные экземпляры.

### Два режима наград

- `ALL` — выдаёт все предметы из набора.
- `RANDOM` — выбирает один предмет согласно положительным весам.
- Результат RANDOM выбирается на сервере и записывается до выдачи.
- Сериализация Paper сохраняет название, lore, зачарования, атрибуты, компоненты и PDC предмета.

### Безопасная доставка

- Предметы сначала добавляются в инвентарь игрока.
- Невместившиеся предметы записываются в SQLite.
- `/envelope claim` повторно выдаёт ожидающие награды.
- В мире не создаются лишние Item Entity.
- Открытие резервируется транзакцией до удаления конверта из инвентаря.

### Визуальная часть

- В комплект входит ресурс-пак с оригинальной текстурой `pixil-frame-0.png` 16×16.
- Используется современный item model `ovenquill:envelope`.
- Без ресурс-пака механика продолжает работать с базовым предметом.
- ПКМ запускает открытие, Shift + ПКМ — защищённый предпросмотр.
- Анимация использует звук и небольшое количество частиц.

### Минимальная нагрузка

- Нет постоянного сканирования игроков, миров или инвентарей.
- Нет фоновых задач, выполняющихся каждый тик.
- Одно SQLite-соединение и один daemon-поток вместо пула.
- SQL выполняется вне основного потока сервера.
- Используются WAL, `synchronous=NORMAL`, индексы и prepared statements.
- Активные типы хранятся в неизменяемом snapshot-кэше.
- Анимации существуют только во время открытия и имеют общий лимит.
- Награды при переполнении записываются в очередь, а не создаются в мире.

## Установка

1. Установите Paper или совместимую сборку Purpur для Minecraft 26.2.
2. Используйте Java 25 или новее.
3. Остановите сервер и сделайте резервную копию.
4. Скопируйте [`OvenquillEnvelopes.jar`](OvenquillEnvelopes.jar) в `plugins/`.
5. Запустите сервер для создания конфигурации и базы.
6. Установите [`OvenquillEnvelopes-resourcepack.zip`](OvenquillEnvelopes-resourcepack.zip) как серверный ресурс-пак или включите его в основной пак OVENQUILL.
7. Настройте права через LuckPerms либо стандартный Bukkit permission API.

Не удаляйте и не заменяйте `plugins/OvenquillEnvelopes/secret.key`: смена ключа сделает ранее выданные конверты недействительными.

## Быстрый старт

Возьмите предмет-награду в основную руку:

```text
/envelope create starter all
/envelope give Player starter 1
```

Для случайной награды:

```text
/envelope create lucky random
```

В версии 1.0 команда создания фиксирует один предмет из основной руки. Повторное создание того же ID увеличивает версию шаблона.

## Команды

| Команда | Назначение |
|---|---|
| `/envelope help` | Краткая справка |
| `/envelope admin` | GUI со списком активных типов |
| `/envelope create <id> [all\|random]` | Создать новую версию типа из предмета в руке |
| `/envelope delete <id>` | Архивировать тип |
| `/envelope list` | Показать активные типы |
| `/envelope give <player> <type> [amount]` | Выдать конверты онлайн-игроку |
| `/envelope send <player> <type> [amount]` | Адресная выдача |
| `/envelope giveall <type> [amount]` | Выдать всем игрокам онлайн |
| `/envelope claim` | Получить ожидающие награды |
| `/envelope reload` | Перезагрузить конфигурацию и кэш |
| `/envelope status` | Показать состояние системы |

Алиасы: `/envelopes`, `/env`.

## Настройка производительности

```yaml
performance:
  max-concurrent-animations: 20
  particles-per-step: 4
  animation-step-ticks: 5
```

Увеличение `animation-step-ticks` и уменьшение двух других значений снижает нагрузку. Эффекты можно отключить полностью:

```yaml
opening:
  animation-enabled: false
  particles-enabled: false
  sounds-enabled: false
```

## Хранение и восстановление

Рабочие файлы находятся в `plugins/OvenquillEnvelopes/`:

```text
config.yml
messages_ru.yml
secret.key
envelopes.db
envelopes.db-wal
envelopes.db-shm
```

Для согласованной резервной копии остановите сервер и копируйте всю папку плагина. Статус `OPENING` не завершается автоматически после аварии: администратор должен проверить базу и журнал. Это защищает от повторной выдачи при неоднозначном результате сбоя.

SQLite рассчитана на один backend-сервер. Для общей сети необходимы централизованная БД и распределённая блокировка.

## Сборка

```powershell
gradle clean build
```

Требуются Java 25+, Gradle 9.2+ и доступ к Maven-репозиторию Paper. Результат: `build/libs/OvenquillEnvelopes.jar`.

Полная упаковка:

```powershell
gradle clean deliverables
```

## Состояние версии 1.0.0

Реализовано рабочее ядро: уникальные экземпляры, подписи, ALL/RANDOM, предпросмотр, выдача онлайн, массовая выдача онлайн, безопасная очередь наград, ресурс-пак и русская конфигурация.

Пока не реализованы: расширенный GUI-редактор нескольких наград и весов, календарный редактор, доставка нового конверта офлайн-игроку, группы LuckPerms, автоматическое разрешение аварийных операций и межсерверная БД. Ограничения указаны явно, чтобы документация не обещала отсутствующие функции.
